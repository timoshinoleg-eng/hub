# Совместимость с существующими проектами в MAX

У организации уже есть активные боты. Этот хаб должен встать рядом с ними,
а не сломать их. Ниже — что сделано и что нужно проверить вам.

## 1. Отдельный бот, а не раздел в существующем

Хаб — **отдельный бот**. Причины:

- мини-приложение привязано к боту один-в-один, двух приложений на один бот нет;
- у каждого бота свой токен — поломка рассылки хаба не затронет боевые проекты;
- отдельная модерация: правки карточки хаба не отправят на повторную проверку
  существующие боты.

**Проверьте остаток слотов:** организация или ИП — 5 ботов на профиль.
`business.max.ru/self` → Чат-боты. Если заняты все пять — либо удалите
неиспользуемый, либо поднимайте хаб внутри существующего бота
(тогда мини-приложение заменит текущее).

## 2. Общий домен, отдельный путь

Мини-приложение кладём на **поддомен вашего домена**, а не на новый:

```
https://games.ваш-домен.ru/          ← хаб
https://api.ваш-домен.ru/ev          ← сервер событий
```

Требование платформы: домен только латиницей, цифрой, точкой и дефисом.
Кириллические домены не пройдут.

## 3. Кросс-промо между своими проектами

Самый дешёвый канал: каталога мини-приложений в MAX нет, а ник вида
`idИНН_bot` запомнить невозможно. Поэтому каждый ваш бот — это вход
для остальных.

Заполните `bot/config.mjs`:

```js
export const SISTER_PROJECTS = [
  { title: 'Название проекта', url: 'https://max.ru/id0000000000_bot' },
];
```

Бот добавит до двух ссылок в меню (платформа допускает не более трёх
кнопок-ссылок в одном ряду).

## 4. Разделение данных

Если у существующих проектов уже есть Postgres — хаб не мешает:
все таблицы с префиксом `hub_`. Схема создаётся сама при старте
(`CREATE TABLE IF NOT EXISTS`), миграции не конфликтуют.

Хотите полностью отдельно — задайте отдельную БД в `DATABASE_URL`.

## 5. Общие секреты

Один `.env` на все процессы хаба. Не переиспользуйте токены существующих
ботов: у каждого бота свой токен, и токен может быть отозван за нарушение
Правил платформы — тогда пострадает и тот проект, чей токен вы взяли.

## 6. Реквизиты в одном месте

`bot/config.mjs` → `ORG`. Оттуда же подставляются ссылки на политику и
оферту в команде `/legal`. Если у организации уже опубликованы политика и
оферта — укажите **существующие ссылки**, не плодите новые документы.

## 7. Что уже проверено автоматически

`npm run smoke` гоняет три проверки без сети и без токена: ассеты игр,
20 проверок эндпоинтов сервера и все сценарии бота на настоящих `Context` и
`Keyboard` из SDK. Клавиатуры при этом сверяются с лимитами платформы,
а выгрузка — на отсутствие сырого `user_id`.

Это не отменяет ручной проверки на устройстве, но снимает почти всё, что
иначе всплыло бы уже после модерации.

## Порядок запуска

1. `npm install && npm run smoke` — должно быть зелёным.
2. Проверить остаток слотов ботов; создать бота, дождаться модерации
   (до 48 рабочих часов), взять токен и ник.
3. Заполнить `.env` и `bot/config.mjs`, заполнить `HUB_CONFIG` в `index.html`.
4. Опубликовать политику ПДн по адресу из `ORG.policyUrl`.
5. Залить статику на домен, поднять `npm run server` и `npm run bot`.
6. Привязать мини-приложение в карточке бота, кнопка «Играть».
7. Прогнать 100–300 человек, снять метрики: CTR кнопки «Играть», доля
   доигравших, доля поделившихся, доля подписавшихся на уведомление.

## Что требует проверки с вашей стороны

- [ ] Остаток слотов ботов (organisation/ИП — 5)
- [ ] Какой домен выделить под мини-приложение и API
- [ ] Ссылки на уже опубликованные политику и оферту
- [ ] Список проектов для кросс-промо (`SISTER_PROJECTS`)
- [ ] Кто в организации имеет доступ к `HUB_ADMIN_IDS` для команды `/cast`
- [ ] Что кнопка-ссылка `https://max.ru/<ник>?startapp=g<игра>` открывает
      сразу игру, а не меню хаба (проверяется один раз, на реальном устройстве)
